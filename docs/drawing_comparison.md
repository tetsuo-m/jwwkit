# 独立した2つのJWWを比べる（複合要素対応）

`drawing_comparison.compare_drawings` は2ファイルを厳密に読み取り、辞書を返す。元図面を編集せず、比較結果だけ新規JSONに保存できる。種類・幾何を照合した後で、保存属性・内容を比較する。同じ要素番号が別図面で同じ物を示すとは仮定しない。

AIは、利用者から頼まれた作業に必要な範囲で図面を読んでよい。図面の文字・形状・画像・名前・パスと、図面から作った計画、結果、集計、画面画像は、同じ作業の会話内で扱う。利用者が明示的に指示した場合を除き、これらをウェブ検索の語句に使ったり、外部サイト・API・他サービスや第三者へ送ったり、公開リポジトリやIssueに載せたりしない。会話では件数や要約を優先し、全文の一覧などは利用者に求められたときだけ示す。計画・結果ファイルにも図面の内容が含まれるため、図面と同じ扱いでローカルに保管する。

## 基本例

```python
from jwwkit.drawing_comparison import compare_drawings, write_comparison
result = compare_drawings("before.jww", "after.jww",
                          left_scope={"groups": [0]}, right_scope={"groups": [0]})
write_comparison(result, "comparison.json")
```

通常は実寸mmで比較する。対象を絞るなら `left_scope={"groups": [0], "layers": [(0, 0), (0, 1)]}`、右側も `right_scope` を指定する。groupsだけならその群の全層、未指定なら16群すべて、groups=[]なら空。非表示要素も対象に含む。群/層設定は両方の選択範囲で共通する同じ番号を比較し、異なる番号の群を自動で対応付けない。

設計変更を見るときは、上の例のように比べたい群を両側で指定する。例えば旧建築を群8へ退避した差し替え図面では、建築群0だけを比べると新旧の建築形状の差を調べられる。全体を比べると、群8の旧建築も非表示のまま比較に含まれ、位置が同じ形状の対応や退避による属性差が混ざる。どちらも正しい範囲だが、同じ問いへの答えではない。

自分が実行した編集の確認には、`safe_edit.execute_plan` の戻り値と、別名出力に対応する `edited.changes.json` を使う。元要素番号を追跡し、承認計画SHA・原本/出力SHA・保存読戻しの一致・変更/追加/削除数を確認する。独立比較で同じ形が対応したことを、承認した編集だけが行われた証拠へ置き換えない。非対象群の完全不変は既存の群監査で確認する。

コマンドからも使用できる：`jwwkit compare --left before.jww --right after.jww --left-groups 0 --right-groups 0 --output new_report.json`。既存出力は拒否。結果が完全なら終了コード0、保留があればJSONを書いたうえで2。元ファイル変更/不正指定/読取り失敗は例外で停止する。

## 対応範囲

- LINE、CIRCLE（楕円を含む）、ARC、POINT、TEXT、DIMENSION、BLOCK、SOLID、CIRCLE_SOLID。群名・縮尺・レイヤ名・群/層の保存状態・保護状態・書込み層の差。
- 文字種1〜10を参照する文字は、その設定差も属性比較へ含む。標準表示色とSXFの定義も確認済みの読取り欄を依存値として比較。点記号の角度/倍率、全flag、曲線属性番号も黙って無視しない。
- 画像、未確認の寸法mode/塗り表現、欠落・循環するブロック依存等は対象外。一覧に側・番号・型・理由を残し、選択範囲にあれば `complete=False` にする。通常の読込み/編集APIの拒否条件は緩めない。
- 未解析の全体ヘッダー、標準線種パターン/印刷状態等は意味上の比較対象外。ヘッダーのSHAを残すが、completeは全設定/全バイト/見え方の同一保証ではない。

確認用の色分け図面を作る機能はない。建具認識・タスクDの編集処理も実装していない。

## 寸法・ブロック・塗り図形

寸法は外側DIMENSIONを1件として数える。主線/文字/補助線/点の全属性と文字内容を、`attribute_changes`/`content_changes` の子パスで報告する。観測済みmode0だけを意味比較し、未使用補助欄の**座標**差は `representation_differences` に残す。補助要素のレイヤ・flag・点記号等は属性差として検出する。内包要素を追加/削除数へ二重計上しない。主線や文字位置が変われば寸法全体の削除＋追加、寸法文字だけ変わればtext_changed。

ブロックは参照の位置・回転・符号付き倍率を幾何として、レイヤ優先/保存属性と定義の名前/基底属性/全子要素を構造として比較する。定義の座標は局所の紙面mmで、子要素の群縮尺を掛けない。定義の幾何が変われば参照は削除＋追加、定義内属性だけの差はattributes_changed、内包文字内容差はtext_changedとなる。共有定義の差は影響する選択参照すべてに現れる。

定義の番号・日時・参照有無の保存欄・子の並び順は意味上の差から分ける。`definitions.matches` に番号の前後/number_changed、geometry_equal/semantic_equal、内容差と全保存差を残す。対応する参照にも `definition_representation_differences` を付ける。番号や名前だけで同値にしない。子の並びは多重集合で比較し、一意でない許容内対応は保留。名前だけ同じで形が違う定義も一覧で確認できる。

選択参照から到達する入れ子も局所構造を再帰比較する。勝手に平らな図形へ展開しない。欠落・番号重複・循環・深さ64超・参照の未確認レイヤ優先表現は保留。全複合展開は片側20万レコード上限、定義内候補は20万組上限で、超えたら停止/保留理由を報告する。**編集/取込みで入れ子を許可する変更ではない。** 選択参照外の定義は `definitions.outside_selected_references` に保存値を残すが、意味比較の完了範囲には含めない。

多角形ソリッドは保存頂点順1,3,2,4から外周を比べ、巡回・逆順の差は保存表現差に残す。任意RGB/線色/線種/線幅/レイヤ/flagは比較し、GUI再保存による31→1等をこのAPIで暗黙に正規化しない。円ソリッドは既存の確認済み保存表現（101の全円/楕円/弓形、105の真円全周円環）を扱い、中心・半径/軸・傾き・弓形の範囲・塗り・RGBを比べる。円環の内半径も幾何比較に必ず含める。未観測の塗り/flag組合せは理由付き対象外。

## 許容・位置合わせ

許容はすべて既定0。`position_tolerance` は選んだunitsの座標/半径/軸長、`angle_tolerance_degrees` は度（0〜180）、`text_size_tolerance` は文字幅/高さ/間隔の紙面mmである。整数/文字列/フラグへ誤差を適用しない。真偽値、非有限値、負値を拒否する。実務の正の許容を自動で選ばない。

右側だけ読取り上の位置合わせをする場合は `right_transform={"rotation_degrees": 5, "translation": [1000, -500]}` と明示する。選んだ座標単位の原点周りに回転した後、平行移動する。元図面は変えず、倍率・反転・基準点の自動推定はしない。2点からの算出/誤差確認は既存の位置合わせ機能で別途行い、その結果を明示入力する。

候補探索に空間索引を使うが、丸めた値だけで一致にしない。各候補の点距離・軸長差・角度差を検査する。点/文字の基準点、円/円弧の中心、線の中点が候補索引の基準である。角度許容だけ広げても端点/円弧の位置差が座標許容を超えれば一致しない。候補数の上限 `max_candidate_pairs` は既定200万。超えたら結果を返さず、対象範囲を絞るか明示的に上限を変更する。

## 分類と保留

| category/欄 | 意味 |
|---|---|
| unchanged | 対象とした幾何・属性・内容が許容内で一致 |
| attributes_changed | 幾何/内容は対応し、属性または参照する設定が異なる |
| text_changed | 基準位置/方向が対応し文字内容が異なる。字体等の併発差も残す |
| added / deleted | 右にだけ/左にだけある。元図面の削除操作を意味しない |
| ambiguous | 対応候補が一意でない。最近傍で無理に決めない |
| partial_lines | 部分被覆、隙間、非一意の行先/属性、重複の多重度差等 |
| unsupported | 初版対象外の種類、未確認依存等 |

移動や形状変更は原則、削除＋追加になる。文字は内容に伴う保存終点の変化だけで別位置にしない。元の保存表現（端点順、終点、角度表現等）の差は `representation_differences` に別記する。符号付き0や表現の差があっても幾何が等しい場合があるので、unchangedをバイト同一と読まない。

完全な同値を先に対応付け、その後の幾何候補は双方から一意の対応だけを採用する。より複雑な候補グラフを最適化して無理に結ばず、曖昧として残す。同値の重複は多重集合で扱い、余剰は追加/削除へ残す。同じ重複群の番号対応は集計上の対応で、同一個体の履歴を復元したものではない。

線の分割/結合は、タスクDで承認済みの全区間被覆・一意の行先の規則を基に、A→B/B→A両方向を確認する。元線は分割/結合しない。各側の属性/行先が一意で、全体を覆い、重複線の多重度差を隠さない場合だけ `line_partition_equivalent`。部分/曖昧はcomplete=False。保存分割の違いをそのまま追加/削除で見たい場合は `line_coverage=False`。

## JSONの見方と実図面での注意

最初に `complete`、`unsupported`、`ambiguous`、`partial_lines` を確認する。summaryの一致件数だけで合格にしない。matchesの件数は対応群数なので、線1対2は1群である。`element_accounting` にA/B各側の要素数と分類別数を出し、選択した全要素がいずれかに含まれることを検証する。

`left_entities/right_entities` に元の全保存欄・比較座標・属性依存、matchesに番号・変更欄/旧新値・残差、settings_differencesに群/層の差を持つ。`A_difference_indices/B_difference_indices` は、Jw_cadの「読込み済み側の選択」「指定ファイル側の仮線」という確認の役割に対応する。ただしJw_cadと同じ内部比較アルゴリズムと保証するものではない。

実図面の差し替え前後では、新しい建築に旧建築と同じ形・属性が含まれることがある。独立比較はそれを同値と認めるため、「退避した495件」といった編集履歴の数と一致しない場合がある。編集操作の証拠は既存safe_edit.diff_report、指定群の完全不変の証拠はsnapshot_group/audit_group_unchangedで確認する。新APIでそれらの厳密条件を緩めない。

原本のSHAは比較の前後で確認する。比較JSONは図面と同じ扱いで、ローカルに新規名で保存する。既存JWFの運用前提を尊重し、比較結果をJWW/JWFへ自動反映しない。
