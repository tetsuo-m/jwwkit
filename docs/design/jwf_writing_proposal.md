# JWF作成・書出しの進め方（提案・未実装）

> 設計の記録であり、実装済みの機能ではありません。

## 初版で提案する範囲

利用者が用意したJWFから、新しい名前の派生JWFを作る。公開読取りAPIは実装済みだが、以下の書出し/実行APIはまだない。図面用safe_editへ未対応のJWF操作を渡すものではなく、同じ「計画→チャット承認→SHA検証→実行」という仕組みの専用JWF編集モジュールを作る案である。

初版の変更対象は、既存の有効なLCOLLOR_1〜8、PCOLLOR_1〜8、PCOLLOR_GのRGB3欄に限定する。RGBは整数0〜255、真偽値は拒否する。各行の残りの幅/点半径等と、その単位に関わる設定は変更しない。全欄を再組立てして正常化するのではなく、確認したRGBの字句範囲だけを差し替える。対応対象は実装前に同梱書式と既存実ファイルの表現で再確認する。

新規作成も当面はこの「確認済み原本の派生」を使い、白紙からの完全な設定生成は別段階とする。Sampleの値例を全キーの既定値だとみなさない。要約JSONだけから元にない設定や欠けた名前を生成しない。

## 1. 計画

依頼例：「印刷色1を青へ変えた別名JWFを作りたい」。参照JWFのパス/サイズ/SHA、出力先、キー/行/欄、旧値/新値、変更範囲、原本の診断と未確認欄をJSONへ出して終了する。AIがその一覧と計画SHAをチャットへ示す。人の承認を待つ。依頼にない設定、書込み/表示状態、線幅は変えない。

対象キーの欠落・重複・END後の非活性・構文未確認・対象値の不完全CP932は拒否する。未対応のキー/欄は理由を示す。キー追加やEND移動、A-Read/A-Read0追加、起動時自動適用、Jw_cad/レジストリの操作は初版の対象外。

## 2. 承認後の書出し

承認された計画SHAと元JWFのSHA、対象の元バイト/値を再検証する。相違があれば書き出さない。出力先が既存なら停止する。原本を書き換えず、承認されたRGBの字句以外の全バイトが一致する候補を作り、検査後に新規ファイルへ保存する。

利用者JWFのLAYNAM_0の不完全CP932やLAYNAM_Aの欄数超過は、承認対象外の生バイトとしてそのまま保持する案とする。修復・置換・切捨てはしない。対象行/変更位置を確実に分離できないときは拒否する。異常な原本の全体を正しいJWFと保証しない。

## 3. 読戻しと利用者への報告

生成物を読戻し、指定した欄の新値・変更数、未変更範囲の全バイト一致、原本不変、診断の増減、出力SHAを報告する。新しい要約は元を上書きせず、生成JWFのSHAに結び付けた別ファイルへ作る。利用者の運用意図を、自動的に別の設定ファイルへ転用しない。

Jw_cadへ自動読込みしない。利用者が自身の環境で必要時に読み込み、表示・印刷を確認する。AIは設定の優先関係や反映結果を保証せず、JWWの全体設定へ同期しない。MHENなど既存図面へ影響し得る設定が残ることを説明する。レジストリ復元はAIが行わない。

## 受入れ案

- 合成JWFで、RGB3欄のみの正確な書出し、CP932/コメント/空白/CRLF・CRCRLF/END/未変更範囲の全バイト保持を確認する。既存ReaderとWriterが互いに誤りを打ち消さないよう、期待する完成バイト列も独立に比較する。
- 不完全文字を含む原本でも対象外の全バイト保持を確認し、不完全な対象欄・重複・未指定・範囲外・未知構文は変更前に拒否する。
- 計画改変、元ファイル改変、対象改変、出力重複を意図的に起こし、原本無変更で停止することを確認する。
- 実ファイルで派生JWFを出す場合は、対象一覧とSHAを利用者へ示し、その計画の承認後だけ実行する。生成物の宣言値検査と、人による見え方確認を区別する。設定優先のGUI対照は再開しない。

## 拡張候補

文字種/フォント、線幅/点半径、背景、寸法、グループ名/層名、白紙からの最小JWF生成は、欄の意味・単位・依存関係を確認した範囲で追加する。複合フラグや未解析値を初版に混ぜない。JWWとの同期やJw_cadへの適用は、JWFの書出しとは別の機能として扱う。

この提案を確認してから実装する。現時点では公開書出し関数や実行済み出力はない。
